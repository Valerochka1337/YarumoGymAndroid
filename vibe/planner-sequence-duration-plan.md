# Последовательность и время AI-плана

Базы: Android 449de43, backend 1921b3f. Один владелец реализации; без агентов, внешнего inference, публикации и устройства. Backend: /private/tmp/ValerochkaGymBackend-planner-sequence-duration.

- T-001 / AC-001: проверить capture → eligibility → context → result синтетической историей; сохранить даты, actual/legacy, разделение недавних/недельных данных.
- T-002 / AC-002: сводка последней нагрузки, последовательность акцентов без механического запрета повторов; валидируемое объяснение выбора.
- T-003 / AC-003: единый estimator и одинаковые fixtures 30/60/90 минут, силовые/timed/cardio, отдых/переходы/разминка. Допуск max(300 секунд, 20% желаемого времени) — инженерный, не медицинский.
- T-004 / AC-004: отдельный optional GET пояснения; существующий wire/drafts/approval не меняются. Числа и повторы вычисляет backend. UI различает запрос и оценку, пояснение относится к исходному варианту.
- T-005 / AC-005: регрессии, сравнительная AI-рубрика, финальные unit + debug Android, backend test/build; ограничения свидетельств и ручная проверка.

Совместимость/выкат: сначала backend с additive endpoint и SQL migration, затем Android. Старый клиент получает прежние DTO; новый при отсутствии ресурса показывает план без пояснения. Имя availableDurationMinutes сохраняется для durable bytes; смысл — желаемая длительность плана, верхняя граница сохраняется. Offline очередь, owner/session/generation/freshness, редактирование и явное принятие не изменяются.
