# Диагностика Live Coach

В debug-сборке события пишутся в Logcat с тегом `LiveCoach` через `CoachDiagnostics`.
В release этот поток отключён. Синхронизация и другие фоновые задачи в него не входят.

Фильтр Android Studio: `tag:LiveCoach`. Через ADB:

```bash
adb logcat -v threadtime 'LiveCoach:D' '*:S'
```

## Что видно

- `conversation.*`: постановка сообщения в очередь, этапы обработки, локальные команды,
  итог, повтор, подтверждение/отмена предложения и undo.
- `network.*`: получение промпта и списка моделей, отправка потока, первый текст,
  завершение, ошибки и отклонённые проверки контракта. `request` связывает поток с запросом backend.
- `agent.*`: обращения к модели, названия инструментов и результат их выполнения.
- `context.snapshot.*`: доступность контекста, ревизия, количество упражнений и подходов.
- `autoregulation.*`: числовые входы RIR, порог, выбранная ветвь расчёта,
  отсутствующие сведения, предлагаемые изменения веса/повторов/отдыха.
- `initiative.*`: источник проверки, выбор сообщения или причина пропуска:
  `disabled`, `pending_interaction`, `already_asked`, `no_change`.
  Ограничений по интервалу и общему количеству автоматических сообщений нет.
- `editor.*`: сохранение предложения, проверка актуальности расчёта, итог применения.

`trace` связывает начало и завершение одной операции; `elapsed_ms` показывает длительность.
`unknown` означает отсутствие значения. Например, `decision=CLARIFY rule=unknown_set_type
missing=SET_TYPE` означает неизвестный тип; автоматический вопрос по нему подавляется.
`rule=recorded_effort` означает сохранение плана при записанном или неизвестном фактическом RIR.
Целевой RIR больше не запрашивается; `confirmed_harder_adjustment` требует явного сообщения, что стало тяжелее ожидаемого.

Проверка инициативы запускается при изменении тренировки или плана отдыха и раз в минуту
для временных условий. Секундный отсчёт, прогресс ожидания пульса и смена цвета уведомления
не запускают повторный расчёт. Числовая коррекция подхода учитывается даже без изменения ревизии.

Переписка, промпты, полные аргументы инструментов, тела ответов, данные аккаунта и токены
не выводятся. У исключений сохраняются тип и места возникновения (включая вложенные причины),
но не свободный текст `message`, который может содержать данные запроса. Логи содержат
числовые тренировочные параметры, необходимые для объяснения расчётов.

`autoregulation.adjacent` записывает previous/current weight и reps, rep_drop и фактический RIR без текста пользователя. Правила 1.2.0: `adjacent_rep_drop`, `below_five_reps`, `above_fifteen_reps`. ADVISE — совет без числового пакета и без обязательного ответа.

В инициативе 1.3.0 после выбора события ожидаются conversation.enqueue и agent.turn. Отсутствие приветствия нормально; результат локального расчёта служит триггером ИИ, а не готовым текстом чата.


HTTP-ошибки содержат числовой статус и безопасную метку причины `http_reason_0`.
Например, `unfinished_tool_dialog` означает отклонение структуры диалога бэкендом.
Метки получаются только из списка известных ошибок; произвольные code/message ответа
не выводятся. `network.http.retry` показывает номер повтора (1–3) и задержку (1000/2000/4000 мс).
`network.stream.dispatch` содержит последнюю роль, наличие системных сообщений после начала
диалога и лимит HTTP-повторов. Содержимое сообщений не логируется.
