# Yarumo coach — дизайн-система (актуальная)

Дата актуализации: 2026-09-01 (Material You, светлая/системная тема, adaptive layout и
accessibility-контракт). Это
**источник правды** для любой новой UI-разработки.
Заменяет раздел 4 «Дизайн-система (вариант C)» в
[спецификации приложения](superpowers/specs/2026-07-31-valerochka-gym-design.md).

Стек: Jetpack Compose, **Material 3 Expressive** (`MaterialExpressiveTheme`), Material You.
Системная тема и системная динамическая палитра включены по умолчанию; пользователь может
независимо выбрать режим System/Light/Dark и одну из фирменных палитр.

---

## 1. Принципы (6 правил)

1. **Material You по умолчанию.** Системная палитра следует обоям. Фирменные варианты
   (`AccentColor`: зелёный · лаймовый · голубой · коралловый) доступны как явный выбор и задают
   полный light/dark tonal scheme. Акцент применяется семантически: главные действия, активные
   состояния, прогресс и важные числа. `error` — только ошибки и деструктивные действия.
2. **Плоско.** Никаких градиентов и «свечений». Глубина создаётся тональными ступенями
   `surfaceContainer*`, а не заливкой-градиентом.
3. **Больше иконок, меньше текста (умеренно).** Очевидные подписи заменяем значком или парой
   «иконка + значение». Не превращаем в ребус: подписи вкладок и неочевидные вещи оставляем текстом.
4. **Пружинная моторика.** Движение — на пружинах M3 Expressive (лёгкая «дотяжка»), а не линейный tween.
   Переходы между вкладками — исключение (см. §7).
5. **Адаптивность, а не “версия для планшета”.** Решения принимаются по `WindowSizeClass`:
   navigation bar на compact, navigation rail на medium/expanded, max width или list-detail для
   широкого окна. Критичный контент не пересекает fold/hinge.
6. **Доступность является поведением.** Touch target не меньше 48dp; экран работает при
   `fontScale = 2.0`; цвет и Canvas не являются единственными носителями смысла или действия.

## 3. Цвет

**Всегда** берём цвет из `MaterialTheme.colorScheme.*`. **Никогда** не хардкодим `Color(0x…)` в экранах
и не импортируем токены из `Color.kt` напрямую в UI (палитра меняется в одном месте — теме).
Foreground использует парную `on*`-роль своего background. Dynamic scheme строит Android,
фирменные схемы задают полный набор ролей для light и dark.

Ходовые роли:

| Роль | Где применять |
|---|---|
| `primary` / `onPrimary` | Главная кнопка, активная иконка, ключевое число — текущий акцент |
| `primaryContainer` / `onPrimaryContainer` | Мягкий акцентный блок (напр. баннер «Тренировка идёт») |
| `background` / `onBackground` | Фон экрана, заголовок экрана |
| `surfaceContainerHigh` | Фон карточки (`GymCard`) |
| `surfaceContainerHighest` | Приподнятый элемент внутри карточки (напр. бейдж подхода) |
| `onSurface` / `onSurfaceVariant` | Основной / второстепенный текст и декоративные иконки |
| `error` | Только ошибки/деструктив (удаление, статус «Ошибка выгрузки») |
| `outline` | Тонкие разделители/обводки |

Правило: если тянет добавить новый цвет — почти всегда нужен `surfaceContainer*` (для глубины) или
`primary` (для акцента), а не новый оттенок.

**Исключение — шкалы данных** (`ui/theme/ChartPalette.kt`). На тепловых картах цвет
кодирует *величину*, а не идентичность, поэтому используются фиксированные красная, янтарная и
зелёная ступени, обязательно с легендой. Карта нагрузки движется от красного «мало» к зелёной
«норме» по зонам `VolumeZone`. Сегментная карта InBody движется к красному при дефиците мышц
(`<90%` — красный, `90–99%` — янтарный, `≥100%` — зелёный) или избытке жира (`≤100%` — зелёный,
`101–160%` — янтарный, `>160%` — красный); сегмент без напечатанного процента остаётся серым.
Шкалы **не** следуют за акцентом. За пределами графиков этой палитрой пользоваться нельзя:
кнопки и текст — по-прежнему один акцент плюс `error` для ошибок.

**Предложения AI-планировщика** не показывают статусы или отдельные статусные цвета.
Удаление доступно из меню карточки с подтверждением, как у личных программ.

**Режим и палитра.** `theme_mode` и `palette_mode` хранятся в DataStore. `SYSTEM` для темы
следует конфигурации Android, `SYSTEM` для палитры использует dynamic color. Последний фирменный
`accent_color` хранится отдельно, поэтому возвращение из системной палитры восстанавливает выбор.
Фирменный вариант также выбирает соответствующий launcher alias; в системном режиме Android
может применить monochrome themed icon. Связку `AccentColor.aliasName` ↔ манифест сторожит тест.

## 4. Форма

Скругления берём из `MaterialTheme.shapes` (`GymShapes`): `extraSmall 8 · small 12 · medium 16 ·
large 24 · extraLarge 32`. Углы **симметричные** (старые асимметричные `24/24/24/8` убраны).

- Карточки — `large` (24). `GymCardShape` = 24dp, экспортируется для рамок (`border`).
- Поля ввода — `medium`/16.
- Кнопки-пилюли и круглые бейджи — `CircleShape`.

## 5. Типографика

`GymTypography` переопределяет только заголовки (жирные, плотные): `headlineLarge` (28sp ExtraBold) —
заголовок экрана, `headlineSmall`/`titleLarge` — заголовки секций. Остальное — дефолты M3.
Своего шрифта нет. Числовые/длинные значения — `maxLines = 1, softWrap = false`, чтобы не переносились.

## 6. Компоненты (`ui/components/`)

- **`GymCard`** — плоская карточка (`surfaceContainerHigh`, форма `large`). Базовый контейнер контента.
  Опционально кликабельна (`onClick`) с ripple.
- **`PillButton`** — тонкая обёртка стандартного M3 `Button`: главная кнопка с корректными
  minimum size, disabled/loading semantics и опциональной `leadingIcon`. Для второстепенных
  действий — M3 `OutlinedButton`/`TextButton`.
- **`GlowBackground`** — тонкая обёртка фона экрана (плоский `background`; исторически рисовала свечения,
  сейчас — просто фон). Оборачивает контент каждого экрана.
- **`NumberField`** — числовое поле (фильтрация цифр/точки, однострочный label). Для кг/повт/сек/скорости.
- **`SetNumberBadge`** (в `RoutineEditorScreen`) — кружок с номером подхода вместо надписи «Подход N».
  Паттерн «компактный бейдж» переиспользуйте для порядковых номеров.
- **`DragHandle`** — явный grip ровно 48dp для перестановки упражнений. Он стоит последним
  действием карточки справа; drag начинается после удержания grip (системный long-press).
  Короткое касание или удержание в других местах карточки не начинает перенос.
  Перемещаемая карточка получает тонкую рамку `primary`, соседние позиции — `animateItem` с
  `GymMotion.spatialDefault()`, без теней и дополнительных цветов. Для TalkBack действия
  «Переместить выше/ниже» назначаются на карточку, сам grip не фокусируется.

**Аналитика** (`ui/analysis/`) — свои компоненты, специфичные для вкладки:

- Разделы анализа и замеров — общий `GymSectionTabs` на всю ширину: равные вкладки
  на подложке `surfaceContainerLow`, без рамок и перегородок. Округлая плашка
  `secondaryContainer` перемещается через `GymMotion.spatialFast()`, цвет подписей — через
  `effectsFast()`. Touch target от 56dp; при крупном шрифте подписи переносятся и высота
  растёт. Выбранная вкладка имеет selected semantics и роль Tab. Меню анализа — перед периодом.

- **`AnalysisCard(title, subtitle, icon)`** — карточка блока с обязательным пояснением: почти каждый
  график показывает величину с оговоркой («в среднем за неделю», «оценка по формуле»).
- **`ChipRow` / `ScrollableChipRow`** — переключатели периода/вида/метрики; второй для длинных
  подписей (названий упражнений), где перенос дал бы по чипу на строку.
- **`ValueRow`**, **`ValueBlock`**, **`StatusPill`**, **`LegendSwatch`** — таблица-двойник под
  графиком, статус-бейдж, легенда шкалы. `ValueRow` — для коротких значений (числа, «40 мин»),
  и подпись со значением делят ширину через `weight`; значению длиннее строки место в `ValueBlock`
  (подпись сверху, значение с переносом снизу).
- **`charts/`** — примитивы на `Canvas`: `TrendLineChart` (линия + тренд + выбор точки),
  `ColumnChart`, `ZoneMeter`, `StatTile`, `Sparkline`. Сторонние библиотеки графиков не добавляем:
  правила отрисовки собраны в `ChartSpec`, шкала — в `NiceScale`.
- **`body/BodyMapFlip`** и **`body/BodyMap`** — интерактивная карта тела. Показываем одну крупную
  детальную фигуру и переворачиваем её кнопкой спереди/сзади; раскраска и выбранная мышца при
  перевороте сохраняются. Геометрия — нормированные сплайны в `BodyGeometry`/`BodyShape`, без SVG
  и растра: фигуры гладкие и масштабируются под любой размер, а попадание тапа считается по
  развёрнутой в ломаную кривой с допуском (узкие мышцы иначе не выбрать пальцем). Один компонент
  обслуживает тепловую карту, просмотр и разметку мышц упражнения — раскраска задаётся параметром
  `fillFor`, а `onMuscleClick = null` делает карту только просматриваемой. Инварианты геометрии
  проверяет `BodyGeometryTest`.

**Деталь упражнения** (`ui/exercise/ExerciseDetailScreen`) — pushed-экран, а не редактор:

- название и тип упражнения находятся прямо в M3 app bar; отдельная круглая кнопка
  `Icons.Rounded.Edit` открывает правку, а обычный тап по упражнению — эту деталь;
- повторяющая профильная карточка удалена; карта мышц, прошлый результат, график и рекорды
  разделены на самостоятельные `GymCard`;
- силовая динамика использует `TrendLineChart` для e1RM, timed — суммарные минуты, cardio —
  расчётную дистанцию; выбранная точка всегда дублируется датой и текстовым результатом под графиком;
- при отсутствии завершённой истории показывается объяснение, а не пустой график;
- в пикере библиотеки основной тап выбирает упражнение, поэтому карточка открывается отдельной
  info-кнопкой; в активной тренировке аватар с названием открывает деталь, а в редакторе программы
  заголовок упражнения раскрывает/сворачивает подходы и показывает состояние стрелкой.

**Дополнительный подход в активной тренировке.** Кнопка «+» с доступной подписью
«Добавить подход: <упражнение>» находится в строке счётчика подходов и видна даже при
свёрнутой карточке. Доступна у текущего упражнения и у предыдущего завершённого, пока
в следующих упражнениях нет выполненных подходов. После последнего подхода тренировки
остаётся у последнего упражнения до завершения сессии. Новый подход получает обычный
последовательный фокус; отдельного режима возврата к упражнению нет.

**Профиль.** Валидные изменения сохраняются автоматически без кнопки «Сохранить» и без
блокировки ввода на время записи. Ошибочный ввод остаётся в черновике с сообщением об ошибке.
Начальный диапазон повторений — 8–14, только для отсутствующего профиля; сохранённый
диапазон и явный выбор «Не задан» имеют приоритет.

**Встроенные тренировки и залы.** Стандартные записи сгруппированы в раскрывающемся разделе
«Встроенные» в начале списка, по умолчанию свёрнутом. Пользовательские записи идут ниже без
приписок «Личное» в названиях. Заголовок раздела показывает количество и стрелку, а для
TalkBack сообщает состояние раскрытия. Сворачивание не сбрасывает выбранную программу.

**Карточка программы** — отдельный pushed-экран просмотра состава программы. Пункт
«Открыть» в меню программы открывает название, залы, упражнения, плановые подходы и отдых
обычным текстом. Полей ввода, выбора залов, удаления и переноса упражнений здесь нет.
У личной программы отдельная круглая кнопка открывает редактор; встроенная доступна только
для просмотра и клонирования. Заметка в карточке не показывается. Тап по строке программы на вкладке по-прежнему выбирает
её для старта. Меню личной программы также содержит прямое «Редактировать». Удаление
предупреждает об удалении связанных планов календаря; завершённая история сохраняется.
Подпись происхождения «Стандартное» использует `titleMedium`.

В корне настроек пункт «Тренажёрные залы» расположен сразу после пункта «Тренировка».

**Карточка зала** — самостоятельный pushed-экран просмотра с названием в M3 app bar,
оснащением и доступными упражнениями. Обычный тап по любому залу открывает карточку;
редактирование пользовательского зала доступно отдельной кнопкой. Стандартный зал можно
просмотреть или использовать как основу новой копии, его исходные данные не редактируются.
Редактор группирует название и выбор оборудования, сохраняет поиск и массовые действия;
основное действие — «Сохранить», удаление находится во вторичном меню.

**Клонирование программы и зала.** Действие «Клонировать» открывает диалог с названием
«<исходное название> (копия)» и кнопками «Отмена» / «Сохранить». Пустое название не допускается;
ошибка сохраняет введённый текст для повторной попытки. До сохранения новая запись не создаётся.
Клон становится личным, сохраняя состав исходной записи; оригинал остаётся неизменным.

Паттерн секции: `SectionCard(title, icon) { … }` (см. `SettingsScreen`) — `GymCard` с иконочным
заголовком. Используйте его для группировки настроек/блоков.

Карточка **«Приложение»** в настройках держит версию и весь update-статус в одном месте:
нейтральный текст для проверки/актуальной версии, `error` только для ошибки, `PillButton` для
доступного скачивания или установки и `OutlinedButton` для ручной проверки. Стартовое предложение
обновления — системный `AlertDialog` с тремя разными смыслами: обновить, отложить до следующего
запуска и не напоминать только об этой версии. Прогресс дублируется числом, не кодируется цветом.
Пользовательские статусы и ошибки говорят только об обновлении и следующем действии: названия
GitHub, API, asset, SHA и release-ключа остаются в технической документации.

Основные вкладки используют общий `GymTopBar` поверх M3 `TopAppBar`; pushed-экраны получают
системный Up, не более трёх actions и overflow для остальных. Локальные строки-хедеры допустимы
только внутри pane, где отдельный app bar создаёт ложную иерархию.

## 7. Моторика

**Все спеки — в `ui/theme/Motion.kt` (`GymMotion`)**, единственной точке моторики. Никаких
инлайновых `spring(…)`/`tween(…)` в экранах: composable-код берёт `GymMotion.spatial*()` /
`GymMotion.effects*()` (тонкая прослойка над `MaterialTheme.motionScheme` M3 Expressive),
не-composable лямбды навигации — статические `GymMotion.NavSlideSpec`/`NavFadeSpec`/`TabFadeSpec`.
spatial — движение и размер (слайды, масштаб, высота), effects — цвет и прозрачность (без
пружинной «дотяжки»).

**Переходы навигации** — в `GymNavGraph`, различаем два случая:

- **Вкладка ↔ вкладка** (соседние экраны нижнего меню) → **чистый кроссфейд** `TabFadeSpec`
  (`tween 180ms`, единственный tween в приложении), без слайда. Направление для сиблингов
  бессмысленно и подтормаживает при `restoreState`. Определяется хелпером `isTabSwitch()`.
- **Вглубь/назад** (детали, редактор, активная тренировка) → пружинный слайд:
  `NavSlideSpec` (`spring`, spatial) + `NavFadeSpec` (`spring`, effect). Полноэкранные сценарии
  (`active_workout`, `workout_summary`) выезжают снизу / уезжают вниз (bottom-sheet-ощущение).
  Карточка `exercise_detail/{exerciseId}` — обычный pushed-экран с горизонтальным переходом.

**Микровзаимодействия** — пружины `GymMotion`: `animateContentSize`, `scaleIn`/`fadeIn` для
появления, «пунш»-масштаб при выполнении подхода. Готовые компоненты: `FadeInContent`
(разовое проявление контента после загрузки — вместо «выскакивания» кадром) и `GymFilterChip`
(чип с анимированным выделением). Сторонние анимационные библиотеки не добавляем.

**Данные тоже анимируются** (см. §12): столбцы вырастают от базовой линии, линия тренда
прочерчивается, метка `ZoneMeter` скользит, сетка месяца календаря слайдится в сторону свайпа.
Шкалы, сетки и подписи осей при этом неподвижны — анимируется только слой данных.

Predictive-back включён по умолчанию (targetSdk 37) — отдельного кода не требует; переходы
не следуют за пальцем (seekable-переходы не подключены — осознанное ограничение).

## 7a. Хаптика

Тактильный отклик — через **`ui/haptics/GymHaptics`** (semantic-обёртка `LocalHapticFeedback`):
экраны зовут «что произошло», а не тип вибрации. Карта событий:

| Метод | Тип | Где |
|---|---|---|
| `tap()` | ContextClick | вкладки, выбор карточки/мышцы, открытие упражнения, «пропустить отдых» |
| `confirm()` | Confirm | «Подход выполнен» |
| `success()` | Confirm | завершение тренировки, появление рекордов |
| `reject()` | Reject | отмена тренировки, очистка данных |
| `toggle(on)` | ToggleOn/Off | снятие отметки подхода |
| `step()` | SegmentTick | кнопки ± (вес/повторы/отдых, степперы настроек) |
| `stepFrequent()` | SegmentFrequentTick | точный шаг по long-press, crossing позиции при переносе |
| `dragStart()` | GestureThresholdActivate | grip упражнения захвачен для переноса |
| `dragEnd()` | GestureEnd | grip упражнения отпущен после переноса |
| `longPress()` | LongPress | распознанное долгое нажатие |

Экран получает экземпляр через `gymHaptics()` (`LocalGymHaptics` прокинут из `MainActivity`).
Настройка `haptics_enabled` («Интерфейс → Виброотклик») выключает всё разом: методы становятся
no-op. Вибрация уведомления таймера отдыха — отдельная настройка и отдельный механизм
(`WorkoutSessionService`), к UI-хаптике не относится. Прямые вызовы
`LocalHapticFeedback.current.performHapticFeedback` в экранах запрещены.

## 8. Адаптивная навигация

`MainScaffold` использует Material adaptive navigation suite. На compact это стандартная
`NavigationBar`, на medium/expanded — `NavigationRail`. Подписи остаются, выбранная иконка filled,
невыбранная outlined, индикатор использует стандартный `secondaryContainer`. Insets задаёт
scaffold; собственная форма не должна подменять системный navigation component.

Три вкладки: **Тренировки**, **Календарь**, **Анализ**. «Настройки» — не вкладка: это
pushed-экран, открывается из круглой кнопки-шестерёнки в шапке (`GymTopBar` → `onOpenSettings`).

**Шапка вкладки (`GymTopBar`)** — стандартный M3 app bar с крупным заголовком.
`CircleIconButton` сохраняет визуальную круглую подложку, но интерактивная область не меньше 48dp.
На «Тренировках» живут «+» и настройки; на «Календаре» — планирование и настройки; на «Анализах» —
только настройки.

Контент: compact margin 16dp, medium/expanded 24dp. На expanded одиночная колонка ограничена
примерно 840dp и центрируется; список+деталь используют adaptive pane scaffold. Решение о классе
окна вычисляется в оболочке и передаётся вниз, а не дублируется по экранам.

## 11. Антипаттерны (не делаем)

- ❌ Хардкод цвета `Color(0xFF…)` или импорт токенов из `Color.kt` в экран.
- ❌ Градиенты, радиальные свечения, тени вместо тональной глубины.
- ❌ Второй акцентный оттенок в интерфейсе (в том числе «зелёный» в коде мимо `primary`: акцент
  выбирает пользователь). Шкалы данных — исключение, описанное в §3 и §12.
- ❌ Асимметричные скругления; ручные `RoundedCornerShape` мимо `GymShapes`.
- ❌ Слайд-переходы между вкладками нижнего меню.
- ❌ Иконка без `contentDescription`, если она несёт смысл.
- ❌ Инлайновые `spring(…)`/`tween(…)` в экранах — только токены `GymMotion`.
- ❌ Прямые `performHapticFeedback` — только семантика `GymHaptics`.
- ❌ Интерактивный Canvas без доступного списка/semantic actions.
- ❌ Фиксированная телефонная колонка на medium/expanded или touch target меньше 48dp.

## 12. Графики и данные

Правила отрисовки собраны в объекте `ChartSpec` (`ui/analysis/charts/ChartCommon.kt`); ниже —
то, что нельзя нарушать, даже если «так красивее».

**Форма выбирается по задаче данных, а не по вкусу.**

| Задача | Форма |
|---|---|
| Одно текущее число | плитка `StatTile` (плюс спарклайн), а не график из одного столбца |
| Величина по периодам | `ColumnChart` — **всегда от нуля**, иначе длина столбца врёт |
| Тренд во времени | `TrendLineChart` — **не от нуля**: рост тонет в пустом низе шкалы |
| Значение против нормы | bullet-строка: факт поверх опорных диапазонов |
| Одно значение в коридоре | `ZoneMeter` — линейная полоса с зонами, **не** круговой спидометр |
| Величина по мышцам | карта тела + отсортированный список тех же чисел |

Для карточки упражнения одна ось означает одну сопоставимую между тренировками величину: e1RM
для силового упражнения, суммарное время для timed и расчётную дистанцию для cardio. Сырые значения
прошлого раза и рекорды идут отдельными текстовыми карточками, а не второй осью на том же графике.

**Метки.** Линия 2dp, маркеры ≥ 8dp с кольцом цветом поверхности, столбец не толще 24dp и не
шире 60% своего слота (воздух между столбцами и есть разделитель — рамку вокруг метки не рисуем).
Сетка и оси — сплошные волосяные линии на тон от поверхности, **никогда не пунктир**.

**Подписи.** Число не ставится над каждой точкой: подписываются края осей, последняя точка и
выбранная. Всё остальное читается в таблице-двойнике под графиком (`ValueRow`) — поэтому выбор
точки ничего не «запирает» и цвет нигде не остаётся единственным носителем смысла. Текст носит
текстовые токены, а не цвет данных. Подпись, которая не влезает, **переносится или сокращается
многоточием**, но не обрезается по букве.

**Чего не делаем.**

- ❌ Две оси Y на одном графике. Две разные величины — два графика или переключатель метрики
  (подходы / тоннаж).
- ❌ Радужные и многоцветные последовательные шкалы. Разрешены только ступенчатые семантические
  шкалы `ChartPalette` для карты нагрузки и сегментной карты InBody, всегда с легендой (§3).
- ❌ Один цвет для противоположных смыслов. Перебор объёма отмечается обводкой и словом, а не
  вторым красным: заливка обязана оставаться монотонной.
- ❌ Фильтр внутри карточки. Период выбирается один раз над всем экраном, иначе соседние графики
  показывают разные срезы.
- ❌ Нули вместо пустого состояния: пустая история — это объяснение, а не графики из нулей.
- ❌ Сторонние библиотеки графиков. Примитивов в `charts/` хватает, а их поведение под контролем.

## 13. Live Coach активной тренировки

Контракт функции: `vibe/live-coach-product.md`. Чат открывается из активной тренировки и
уведомления тренера; после завершения занятия тот же диалог доступен для чтения из итогов
и истории. Экран использует обычный pushed-route либо штатную шторку, существующие адаптивные
отступы, `GymCard` и типографику темы.

Сообщения имеют явную подпись роли. Статусы ожидания и ошибки передаются текстом и semantics,
а не одним цветом. Быстрые фразы — обычные доступные кнопки с переносом/прокруткой при крупном
шрифте; поле ввода учитывает клавиатуру и системные insets. Длинное сообщение не обрезается
фиксированной высотой. Список использует стабильные ID сообщений.
До первого сообщения пользователя доступны только «Тренажёр занят», «Слишком тяжело» и
«Добавь подход» (автоматическое приветствие их не скрывает). Затем показываются только
0–4 контекстуальные реплики из последнего ответа модели. Нажатие сразу отправляет реплику;
во время запроса кнопки недоступны. Новое сообщение или действие убирает старые варианты.
При открытом предложении используются его отдельные кнопки подтверждения.

Изменение, выбранное тренером, показывается карточкой «Было» / «Станет» с конкретными
упражнениями, подходами и значениями, затем кнопками «Применить» и «Отмена». Пока идёт применение,
повторное нажатие блокируется и статус объявляется accessibility. Применённое, отменённое и
устаревшее предложение имеют понятный текстовый результат. Кнопка отмены последнего изменения
доступна только когда операция ещё обратима; конфликт не скрывается.

В завершённой тренировке поля отправки и исполняющие кнопки отсутствуют. Импортированный
диалог не создаёт исполняющих предложений. Пользователь может отключить инициативу до конца
занятия. Уведомление нового сообщения открывает этот чат и скрывает содержание на экране блокировки;
отказ в уведомлениях не ограничивает чат внутри приложения.

## Подтверждения Live Coach

Предложение — `GymCard` со списком действий: смысловая иконка, заголовок и короткие
строки изменений. Замена показывает названия и краткую итоговую нагрузку без перечня
старых подходов. Правка подходов показывает только изменённые поля; перенос —
назначение, обмен — названия обоих упражнений. Цвет не заменяет текст.
Кнопки «Применить изменения» и «Отклонить» относятся ко всему пакету и переносятся
на новую строку при недостатке места. Сохранённые предложения старого формата
используют блоки «Было / Станет».

### Активная тренировка: подходы и ориентация

Все экраны приложения запрашивают портретную ориентацию через MainActivity. Android 17
может игнорировать этот запрос на больших экранах; адаптивная вёрстка сохраняется.
Под упражнением находится раскрывающая строка «Подходы: выполнено/всего» со стрелкой
и доступным состоянием раскрытия. Текущее упражнение раскрывается автоматически при
переходе к нему; остальные изначально свёрнуты. Пользователь может свернуть любое упражнение.
Кнопка заметки — `Icons.Rounded.EditNote` (заметка с карандашом) рядом с номером активного подхода,
с touch target 48dp. Сохранённая заметка показывается под подходом. Личная подсказка
упражнения и действия над ней на экране активной тренировки не показываются.

Неактивные подходы компактны: будущие строки не ниже 36dp, выполненные — не ниже 48dp
для редактирования факта. На итоговом экране показываются только упражнения хотя бы с одним
выполненным подходом. Отдельные кнопки истории чата, сохранения и подготовки следующей тренировки
удалены; основное действие — «Готово».

### Потоковый текст Live Coach

До первого фрагмента сохраняется статус ожидания. Затем отображается только текст ответа;
JSON, quick_replies и аргументы инструментов никогда не появляются в черновике. Ошибка удаляет
предварительный текст и оставляет существующий повтор. Финальный ответ сохраняет ID черновика.

Параметры `GymMotion.CoachFrameMillis=32`, `CoachCatchUpMillis=192`, `CoachWordLookAhead=12`
задают быстрое сглаживание по границам слов/графем. Каждый полученный хвост имеет собственный
deadline, поэтому новые фрагменты не откладывают старые. Отключённые системные анимации выводят
текст сразу. При открытии чата накопленный текст не анимируется заново; закрытие чата не отменяет
сервисный запрос. Прокрутка следует за ответом только у нижней границы списка; чтение истории
отключает её, в том числе при появлении клавиатуры. TalkBack получает начало/завершение ответа;
текущие фрагменты заменены стабильным описанием «Тренер отвечает» без live region на тексте.

### Планирование

Экраны ИИ-подготовки и предложений используют `PlanningScreen`: постоянный M3 app bar
с кнопкой назад, прокручиваемый контент с ограничением ширины 840dp и учётом клавиатуры.
В ИИ-подготовке основная кнопка закреплена под формой.

Большие каталоги открываются через `PlanningChoiceField` в шторке `PlanningChoiceSheet`:
поиск, lazy-список со стабильными ID, чекбоксы и фильтр «Выбрано». Форма показывает краткое
резюме выбора; полный каталог никогда не разворачивается внутри неё. Выбор применяется сразу,
«Готово» закрывает шторку; режим одного значения закрывается после нажатия на строку.
Дата и время выбираются через `PlanningDateTimeFields`; часовой пояс автоматически берётся
с устройства и не показывается отдельным полем. Сохранённый момент не меняется при смене
зоны: обновляется только локальное отображение. DST-пропуски требуют другого времени.

Предложение сначала показывается для чтения. «Изменить план» открывает поля; после закрытия
редактора резюме показывает именно тот вариант, который будет применён. Некорректный ввод
не позволяет завершить редактирование. Добавление упражнения требует явного выбора,
уже добавленные упражнения исключаются из выбора. Для подхода видны параметры повторений
или времени; переключение типа очищает несовместимые значения. Новый подход повторяет
плановые параметры предыдущего.

В календаре остаются сетка месяца и primary-кнопка «AI-план» с иконкой AutoAwesome.
Размер кнопки — compact PillButton, как «Замеры» в анализе. При ширине меньше 360dp
или крупном шрифте кнопка занимает отдельную строку под шапкой. Она открывает экран
«Предложения»: заголовок рядом с кнопкой назад, список предложений и единственная
закреплённая нижняя PillButton «Составить с ИИ», открывающая существующую форму подготовки.
Блоки «Новая тренировка» и «Следующая тренировка» отсутствуют. Фоновое получение готового
результата продолжается независимо от видимости карточки подготовки.
Каждое явное нажатие «Начать расчёт» создаёт отдельную заявку и недоступную для открытия
карточку «Тренировка с ИИ» с датой, этапом и неопределённым индикатором прогресса.
Новый запуск, даже с такими же условиями, не отменяет предыдущие расчёты. Карточки читают
сохранённые заявки и восстанавливаются при возвращении на экран. Готовый результат заменяет
свою карточку обычным предложением, не затрагивая остальные. Карточки расчёта показываются
только во время ожидания отправки, очереди и исполнения; при остановке, ошибке или истечении
даты карточка исчезает. Если активных расчётов нет, в списке остаются только предложения.

Просмотр и редактирование предложения используют общие карточки упражнений с формами
программ на вкладке тренировок: аватар, название, тип, сворачиваемые подходы, отдых и поля
плановых значений. Обоснование и уточнение ИИ остаются дополнительными блоками предложения.
Дата и время меняются через «Изменить план»; отдельной кнопки переноса нет.

Статусы предложений, отказ и блокировки по прежнему применению не показываются.
«Сохранить в тренировки» создаёт самостоятельную личную программу; «Применить» также
добавляет её в календарь на дату черновика. Эти действия можно повторять. При пересечении
времени с планом календаря «Применить» недоступно и содержит компактное пояснение
«Тренировка на это время уже запланирована». Длительность определяется общей оценкой
подходов и отдыха, как в списке тренировок. Недоступные упражнения и залы остаются ошибкой.

Исключённые упражнения показываются выбранными строками с явным удалением; добавление
открывает общую шторку поиска. Архивное выбранное упражнение остаётся удаляемым, но не
предлагается повторно. В предложении «Заменить» открывает только доступные по залам
упражнения, отсутствующие в плане. `PlannedSetFields` общий с редактором программы;
тип каталога определяет поля, замена очищает несовместимые значения. Незавершённый
черновик сохраняется локально; применение требует валидного плана и явного подтверждения.

### Strength priorities and workout effort

The STRENGTH profile optionally selects up to five key exercises through the shared searchable
sheet. Each choice has normal/high priority and explicit removal; unavailable choices remain
removable. Completed workout summaries offer optional EASY/MODERATE/HARD effort and clear.
Controls wrap at large font sizes and expose selection semantics. Done awaits persistence;
a failure preserves the editable draft. The backend uses these saved values for the STRENGTH planner; other goals retain their existing behavior.


### Профиль и решения Live Coach

В профиле «Диапазон повторений» необязателен: чипы 3–6, 6–12, 8–15, 12–20,
«Не задан», а также поля «От»/«До» (1–50). Это ориентир, который тренер сопоставляет
с историей упражнения. У карточки остаётся обычный отказ одним нажатием; отдельное меню
«Отклонить с причиной» предлагает сохранение упражнения до конца или отсутствие нужного веса.
Устаревшая карточка исчезает со статусом в чате; повторное подтверждение её не применяет.


Новые сообщения Live Coach уведомляют и поверх экрана тренировки. Уведомления подавляются
только пока соответствующий диалог RESUMED; в фоне доставка возобновляется. Канал сообщений
использует стандартные звук/вибрацию и высокий приоритет, настройки и отказ ОС учитываются.
При входе список открывает первое непрочитанное сообщение; оно выделено рамкой 2dp
`primary` и подписью «Тренер · Новое» со stateDescription «Новое сообщение».
Счётчик прочитанного сбрасывается, но рамка сохраняется до выхода из диалога.
Поступившие после снимка UI сообщения не помечаются прочитанными вместе со старыми.

### Настройки профиля и тренировки

Системная кнопка Back и стрелка в шапке подразделов «Тренировка», «Вид и отклик» и
«О приложении» возвращают к корневым плиткам настроек. Открытый диалог или шторка
сначала закрываются; из корня Back возвращает на предыдущий экран.

«Профиль и аккаунт» — один экран с автосохранением профиля и действиями аккаунта, без списка сессий.
Цель, опыт и пол выбираются из выпадающих списков. Оборудование определяется выбранным залом,
его редактор из профиля удалён. Дата рождения — DatePicker с запретом будущих дат и возможностью очистки. Настройка запрета
профильного напоминания скрыта: отказ сохраняется только кнопкой в диалоге перед AI.
В настройках тренировки Live Coach включается переключателем, модель определяет сервер.
Отдых по пульсу сначала выдерживает длительность из программы/настроек, затем ждёт непрерывного
интервала пульса не выше порога. Переход фаз не выдаёт сигнал завершения отдыха.

### Акценты упражнений

В профиле для любой цели показывается одна компактная строка «Акценты упражнений» с кратким
резюме личных переопределений. По нажатию открывается шторка только с выбранными пользователем
упражнениями и действием «Добавить упражнение». Добавление открывает поиск по живому каталогу,
исключая уже добавленные упражнения, затем позволяет выбрать акцент.
Состояния упражнения: «Акцент», «Обычный», «Реже», «Исключить»; выбор взаимоисключающий.
«Обычный» — явное личное переопределение, а удаление строки возвращает настройку по умолчанию
из админки. Пустой список объясняет, что используются общие настройки.
Нажатия имеют область не меньше 48dp и название упражнения в semantics; варианты переносятся
при крупном шрифте. Изменения используют существующее автосохранение.
Архивные выбранные записи остаются удаляемыми. Legacy-значения оборудования сохраняются
в данных для совместимости.

### Структурированные уточнения и фаза тренировки

Live Coach показывает вопросы на их месте в истории разговора. Быстрые ответы —
необязательное удобство: пользователь может ответить обычным сообщением. Ответ
сохраняется как факт о конкретном подходе даже после окончания отдыха или срока
действия предложения. Изменение плана требует отдельного подтверждения.

Фаза определяется известными событиями: активный отдых — RESTING, переход к другому
упражнению после выполненного подхода — BETWEEN_EXERCISES, иначе — READY.
Наличие незавершённого подхода не доказывает выполнение: приложение не имеет события
начала подхода и не объявляет IN_SET по отсутствию таймера. Ручных кнопок фаз нет. Сообщения о самочувствии
обсуждаются в чате; явный ответ закрывает только указанную жалобу.
